# ECLA DESIGN CONSTITUTION
## Version 3.0 — Living Language World

### 1. Product Design Thesis

Ecla must not feel like educational software.

Ecla should feel like entering a living language world that notices the learner, responds to them, remembers them, and gradually becomes more fluent alongside them.

The visual and interaction standard is:

**Cinematic. Warm. Intelligent. Responsive. Alive. Premium. Human.**

The product should create the immediate feeling:

> “This is not another learning dashboard.”

Ecla is not built around cards, streaks, XP, or generic progress widgets.
It is built around **moments of language use**.

The UI must make those moments feel important.

---

# 2. Core Experience Principle

Every screen must answer one of these questions:

- What can I do now?
- What am I becoming capable of?
- What should I try next?
- What changed because of what I just did?
- What does Ecla remember about me?
- What world am I entering?

If a screen does not help answer one of these, it should be simplified or removed.

---

# 3. The Ecla Emotional Loop

Ecla should be engaging because the learner experiences a repeating loop:

1. **Curiosity**
2. **Action**
3. **Response**
4. **Recognition**
5. **Growth**
6. **Anticipation**

Not:

1. Click
2. Correct
3. +20 XP
4. Repeat

The learner should feel that each interaction slightly changes the world.

Examples:

- a character remembers them
- a competency visually strengthens
- support fades because they no longer need it
- a scene reappears in a different context
- a phrase they learned earlier appears naturally later
- the system recognizes independent performance
- a familiar location evolves across lessons

This creates attachment without manipulative dark patterns.

---

# 4. Signature Identity

## 4.1 Visual Motif — The Language Thread

Ecla's signature motif is **the Language Thread**.

A Language Thread is a subtle luminous strand that represents understanding forming.

It can appear as:

- a quiet line connecting competency nodes
- a faint arc tracing a voice response
- a motion path during scene transitions
- a thin light seam across a completed objective
- a subtle animated underline beneath an important phrase
- a network connecting learned expressions

Rules:

- never random particles
- never confetti
- never neon cyberpunk
- never decorative noise
- always purposeful
- always restrained
- always tied to learning state

The Language Thread should become recognizable as Ecla's visual fingerprint.

# 6. Typography

## Display
Instrument Serif

Use for:
- major scene titles
- emotional achievements
- chapter transitions
- selected hero statements
- reflective progress moments

Never use for:
- navigation
- controls
- dense interface copy
- tables
- small labels

## Interface
Geist

Use for:
- body
- navigation
- controls
- metrics
- labels
- descriptions
- inputs

## Typography Philosophy

Ecla should feel editorial, not decorative.

Large text should breathe.
Small text should be crisp.
Hierarchy must be obvious without excessive weight changes.

---

# 7. Layout System

## Spatial Rule

Do not default to centered card grids.

Use:
- asymmetry
- negative space
- full-width moments
- layered scene composition
- controlled edge-to-edge sections
- contextual panels
- floating secondary controls

## Widths

Reading width: 640–760px  
Primary product width: 1180–1320px  
Scene canvas: fluid  
Dense admin width: 1280–1440px

## Spacing Rhythm

Base rhythm: 4px

Primary spacing scale:
4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 128

Avoid arbitrary values unless required for visual alignment.

---

# 8. Shape Language

Ecla is not pill-everything software.

Use:
- 14–18px standard radius
- 22–28px large experience surfaces
- 999px only for chips, status pills, or circular controls
- sharp geometry selectively in professional mode

No excessive rounded rectangles.

---

# 9. Depth

Premium depth must come from:

1. light
2. overlap
3. blur
4. tonal separation
5. spatial hierarchy

Not heavy box shadows.

Surfaces should feel like layers in space, not floating Bootstrap cards.

---

# 10. Motion Constitution

Nothing moves simply because it can.

Every animation must serve:

- state
- causality
- hierarchy
- emotion
- progression
- spatial continuity

Motion categories:

## Ambient
Slow, nearly subconscious.
Duration: 6–18s.

## Interface
Fast and precise.
Duration: 120–240ms.

## Experience
Scene transitions and major learning state changes.
Duration: 350–700ms.

## Reflective
Mastery, retention, achievement.
Duration: 700–1400ms.

Never:
- bounce everything
- infinite pulsing buttons
- excessive parallax
- random sparkles
- fireworks
- aggressive shake errors

---

# 11. Engagement Without Cheap Gamification

Ecla should be compelling because of:

## Anticipation
“What happens in the next scene?”

## Continuity
“This character remembers me.”

## Capability
“I can actually do this now.”

## Personal recognition
“Ecla noticed I did that without help.”

## Visual growth
“My language world is becoming brighter and more connected.”

## Mastery confidence
“I used this in a new context.”

Avoid dependence on:
- streak anxiety
- punishment
- loot systems
- excessive points
- manipulative countdowns
- forced scarcity

---

# 12. Home Experience

The home screen is not a dashboard.

It is the learner's **current language state**.

Primary structure:

- contextual greeting
- current world / scene
- one dominant next action
- newly earned capability
- one meaningful review prompt
- subtle progress environment

Never show six equal-priority cards.

There should always be one obvious next step.

---

# 13. Scene Experience

The Scene Experience is Ecla's crown jewel.

A scene must feel like entering a place.

Structure:

1. Environment
2. Character
3. Context
4. Language interaction
5. Learner action
6. System response
7. Adaptive continuation
8. Reflection / evidence

Navigation chrome should recede.

The learner should focus on the situation, not the app.

---

# 14. Character Presence

Characters are not avatars.

They have:
- presence
- memory
- expression state
- speaking state
- listening state
- familiarity

Character states:
- neutral
- attentive
- thinking
- encouraging
- amused
- impressed
- uncertain
- speaking
- listening

Characters should change subtly, never cartoonishly.

---

# 15. Mastery Visualization

Do not reduce mastery to percentage bars.

Use a visual state progression:

◌ Exposed  
◔ Developing  
◑ Controlled  
◕ Transferred  
● Retained

Transitions should feel like consolidation.

The visual system should make retention feel stronger than simple completion.

---

# 16. Learning Modes

## Story
Atmospheric.
Character-first.
Slower transitions.
Narrative continuity.

## Drill
Fast.
Minimal.
Keyboard-first.
Near-zero decoration.

## Immersion
Reduced translation.
Environmental context.
More target language.

## Professional
Sharper.
Editorial.
Task-oriented.
Documents, calls, meetings, workplace scenarios.

## Mission
Single objective.
Minimal chrome.
High focus.
Outcome-oriented.

---

# 17. Voice

Voice should feel like communication, not audio upload.

Speaking state:

- character enters listening mode
- surrounding UI dims slightly
- responsive voice field appears
- recording state is clear
- learner sees confidence, not technical noise

Feedback priority:

1. Did communication succeed?
2. Was the message natural enough?
3. What one thing should improve?
4. Detailed scoring only on request

---

# 18. Mobile

Mobile is a primary experience.

Rules:

- full-screen learning scenes
- bottom action zones
- 44px minimum touch targets
- no desktop sidebar compression
- context-sensitive navigation
- gesture-friendly transitions
- mobile-first voice controls
- avoid modal stacking
- respect keyboard viewport

---

# 19. Loading

Never use generic spinners when a meaningful state is available.

Examples:

“Preparing your next step…”  
“Bringing Lucía back into the scene…”  
“Checking what you still remember…”

Loading should feel intentional.

---

# 20. Empty States

Never:
“No data.”

Use contextual language.

Example:

“Nothing needs review yet.

Keep learning. Ecla will bring things back when your memory needs the challenge.”

---

# 21. Error States

Always preserve trust.

Pattern:

- what happened
- whether progress is safe
- what the learner can do
- optional technical details

Example:

“We couldn't load this scene.

Your progress is safe.

Try again”

---

# 22. Accessibility

Premium means accessible.

Required:

- WCAG AA minimum contrast
- reduced motion support
- keyboard navigation
- visible focus states
- text alternatives
- screen-reader labels
- captions/transcripts for audio
- no color-only meaning

---

# 23. Forbidden Design Patterns

Ecla must never become:

- generic shadcn dashboard
- neon purple AI SaaS
- overdone glassmorphism
- childish Duolingo clone
- corporate LMS
- card-grid everywhere
- gradient-heavy startup UI
- icon-wall navigation
- excessive confetti
- fake 3D blobs
- meaningless floating particles
- random animation for “premium”
- cyberpunk learning app
- sterile black-and-white Linear clone

---

# 24. Quality Test

Before shipping any Ecla screen, ask:

1. Does it feel unmistakably like Ecla?
2. Is there one clear primary action?
3. Does the learner understand what changed?
4. Is the interface quieter than the learning moment?
5. Does motion communicate something?
6. Does the screen avoid generic SaaS composition?
7. Does it feel designed for both desktop and mobile?
8. Is the emotional tone warm rather than mechanical?
9. Does it expose capability rather than activity?
10. Would this still feel premium with all animations disabled?

If any answer is no, the screen is not finished.
